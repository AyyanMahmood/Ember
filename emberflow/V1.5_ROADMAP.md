# EmberFlow v1.5 Roadmap

**Planning only — nothing here is implemented.** This is the post-launch roadmap, sequenced by leverage. Every item is grounded in a concrete gap found during the launch-hardening audits, not a speculative wishlist. v1.0 is "correct and launchable"; v1.5 is "correct, fast, and unmistakably premium."

**Sequencing principle:** correctness-adjacent hardening first → then the highest-visible-quality UX lifts → then design-system rollout. Do not start v1.5 until v1.0's live billing validation (`PRODUCTION_VALIDATION_PLAN.md`) is GO.

---

## Explicitly NOT in v1.5 (scope discipline)

- New product features (v1.0 philosophy: "does this help a freelancer run their business better?" — no feature creep).
- Migrating spacing tokens px→rem (tracked separately; only worthwhile paired with unpinning `html { font-size }` — its own device-tested task).
- Provider migration of any kind (Supabase/Vercel/Polar/Upstash are permanent).
- Dropping `paddle_*` columns — a post-launch decommission step, not a roadmap feature.

---

## Suggested order of execution

**A → B → C → E → F → D → G.** Rationale: finish billing-correctness hardening (A) and clear the real security advisory (B) while the billing context is fresh; establish a real perf baseline (C) before any optimization; ship Analytics charts (E) as the biggest visible-quality win; roll out Ember UI (F) so subsequent polish is built on the canonical system; then motion (D) and the broader polish pass (G) on top of the extracted components.
